Metric formulas

Pick the event before you divide

The calculations follow the selected trace. TTFT and TTLT below use nonempty output at the client. E2E ends at the completion marker. Real clients can finish after that marker when they drain or close the transport. A token ID, decoded character, word and streaming callback can each have a different count.

Time to first token (TTFT)
First content − send = 150 − 0 = 150 ms.
Time to last token (TTLT)
Last content − send = 270 − 0 = 270 ms.
End-to-end request latency (E2E)
Done − send = 290 − 0 = 290 ms. Completion tail = 290 − 270 = 20 ms.
Inter-token latency (observed callback gaps)
Gapᵢ = current − previous content arrival. Mean = (40 + 40 + 40) / 3 = 40 ms/gap.
Content-window TPOT
(Last content − first content) / (output tokens − 1) = (270 − 150) / (4 − 1) = 40 ms/token.
Completion-window TPOT
(Done − first content) / (output tokens − 1) = (290 − 150) / (4 − 1) = 46.67 ms/token.
Post-first-delivery user rate
Tokens delivered after first callback / streaming seconds = (4 − 1) / 0.12 = 25 tok/s.
End-to-end user rate
Output tokens / request seconds = 4 / 0.29 = 13.79 tok/s.
Queue, prefill and decode intervals
Queue = 60 − 10 = 50 ms. Prefill to first sample = 140 − 60 = 80 ms. Last sample − first sample = 260 − 140 = 120 ms.

Why do reports with the same metric name disagree?

vLLM documents per-request TPOT as (latency − TTFT) / (output tokens − 1) and pools observed inter-output gaps for ITL. Our two TPOT rows illustrate how the chosen endpoint changes the numerator. The callback log contains no individual arrival times for tokens delivered together. Inventing zero-length gaps inside a chunk would alter the ITL distribution. vLLM's streaming definitions

If the first chunk contains several tokens, dividing its subsequent delivery window by all tokens minus one can make the user look faster. The post-first-delivery rate counts only tokens delivered after that first callback. NVIDIA AIPerf distinguishes content and full-response intervals and describes how its denominator depends on available chunk usage. When N = 1, this lesson leaves TPOT and gap-based rates undefined. SGLang documents a separate zero-TPOT convention for single-token replies in its goodput calculation. AIPerf metric reference · SGLang serving benchmark

Tail latency

Whose experience gets a vote?

Sort the successful requests' TTFT values in ascending order. This worksheet uses the nearest-rank convention, with a one-based rank of ⌈(p / 100) × N⌉. The selected rank's sample is the percentile. A pooled ITL percentile sorts all observed gaps, so a long output can contribute many more observations than a short one.

TTFT percentiles for the selected load

  1. p50 = sample ⌈0.50 × 96⌉ = sample 48 = 150 ms.
  2. p95 = sample ⌈0.95 × 96⌉ = sample 92 = 700 ms.
  3. p99 = sample ⌈0.99 × 96⌉ = sample 96 = 1,600 ms.

With 96 successes, nearest-rank p99 happens to select the maximum. Repeated runs and a larger trace help determine whether the tail persists. A different estimator may interpolate between samples and produce a different p99. Exclude failed latencies only with the failure count visible, since a fast rejection can otherwise improve a latency headline.

Work through pooled gaps and per-request means

Request A streams two tokens with one 100 ms gap. Request B streams ten tokens with nine 10 ms gaps. Both emit one token at each callback. Their individual content TPOTs are 100 and 10 ms/token. The request-weighted mean TPOT = (100 + 10) / 2 = 55 ms/token. The pooled gap mean = (100 + 9 × 10) / 10 = 19 ms/gap.

Nearest-rank p50 of the two request means is the first sorted mean, 10 ms/token. The pooled p95 selects the tenth sorted gap, 100 ms. For fleet-wide percentiles, merge raw samples or compatible histogram counts. Averaging two replica p99 values loses the underlying sample weights and distribution.

Measurement conventions

Make the numbers reproducible

  1. Choose the population and the clock. Record run start/end, warm-up, successes, timeouts and cancellations. Log a monotonic client timestamp for send, every qualified callback, last content and completion. Use server-local durations or synchronized tracing for queue and model time. An unaligned client and server clock cannot yield a one-way network delay by subtraction.
  2. Record the arrival process. Open-loop arrivals are scheduled independently of completions. A closed-loop generator waits for a concurrency slot, so stalls can suppress new arrivals. Keep that client admission wait separate from post-send TTFT. Record offered rate, observed arrivals, in-flight count and test duration.
  3. Define a token and a callback. Prefer output token IDs or trusted usage counts when available. Whitespace, a partial UTF-8 sequence, tokenizer merges, or speculative blocks can change the mapping from content chunks to token counts. Record whether reasoning, tool calls, EOS and empty outputs enter the statistics. A non-streaming response supplies completion latency and token totals but cannot reveal the first-token time or delivery gaps.
  4. Track workload and cache policy. Input tokens/s can count logically presented tokens even on prefix hits. Record reused and newly computed tokens separately if you need prefill compute throughput. Report prompt/output length distributions, model and tokenizer revision, backend version, cache state, sampling settings, device topology, SLOs and percentile convention.

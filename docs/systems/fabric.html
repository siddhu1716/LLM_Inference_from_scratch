Per-token messages

What leaves a rank?

Suppose the previous pass sampled token 42. The engine now feeds token 42 through the model to predict token 43. It batches 32 independent sequences at one new position each. A hidden state is the vector representing one position inside the network. With width 4,096 and two-byte elements, the whole batch of hidden states occupies 256 KiB.

The examples below apply different placements to that same step. Combine placements only when the model and runtime support their interaction. Review the five topology diagrams · Inspect a transformer block

Data parallel One routing decision per request
For two independent dense replicas, the frontend assigns a new chat to replica B. B owns its local KV and processes all subsequent steps. In that deployment the router does not broadcast every hidden state between replicas. Streaming events return to the client. If B fails, a retry needs a surviving compatible cache or a fresh prefill from the prompt. A follow-up chat turn is a new request and can miss cached history if routed elsewhere.
Tensor parallel A collective within a layer
On two ranks, split the input channels of the output projection. Rank 0 computes a partial vector, for example [2, 3], and rank 1 computes [5, −1]. With an all-reduce sum, both receive [7, 2]. For our full batch each rank contributes a 256 KiB partial tensor for this particular projection. Actual wire bytes depend on the collective algorithm and rank count. Other projections may shard outputs locally. All participants must agree on collective order, dtype and count. NCCL collective semantics
Pipeline parallel An activation at each stage boundary
Stage 0 owns layers 0–15 and their KV. Stage 1 owns layers 16–31 and theirs. After layer 15, stage 0 sends a 32 × 4,096 activation tensor to stage 1, a 256 KiB boundary payload in this simple layout. Stage 1 finishes the forward pass. The sampled token IDs must become available to the next iteration's input stage. Microbatch B can enter stage 0 while A is in stage 1. A's next generated token still depends on A finishing both stages. Real model interfaces may send an extra residual tensor.
Expert parallel A dispatch and combine per routed layer
The gate chooses two experts for every token. With 32 tokens, the layer has 64 token–expert assignments. Group rows by destination rank, run the resident experts, return expert outputs, and restore source-token order before summing weighted contributions. Experts on the same rank may share one transport batch. A local assignment may avoid the interconnect. Wide EP can use the same physical ranks for attention and experts. DeepEP dispatch and combine
Context parallel Attention across token positions
Suppose rank A owns positions 0–2,047 and B owns 2,048–4,095. A query at position 3,000 needs valid history from both partitions. One family of methods communicates KV tiles. Another combines local softmax statistics and partial value sums using their relative normalization factors. Summing two independently normalized attention outputs would give the wrong result. The cache layout and the stage doing the exchange depend on the attention backend.

Prefill/decode disaggregation · PD

Transfer a request's history

Prefill and decode are separate model-serving groups. Each group can run the complete model forward path for its phase. The weights are loaded when the workers start. A request changes groups by transferring its accumulated attention state and enough information to resume generation.

  1. Load and register

    Each role loads compatible weights and creates local cache pools and model runners. The connector registers memory or otherwise makes blocks addressable, then exchanges endpoint and layout information. A producer's block ID is local to its allocator. The consumer needs a destination mapping before writing or reading the payload.

  2. Agree on the request

    The router identifies the same request on both sides, including tokenized history, relevant model or adapter identity and generation configuration. Prefill evaluates the uncached prompt positions. Decode admission determines when destination KV slots can be reserved. Early reservation gives transfers a destination sooner but may occupy slots throughout a long prefill.

  3. Publish the continuation

    For the 4,096-token example, prefill produces prompt KV and the final-position logits. In a design where prefill samples the first output, send that token ID and sampling or stopping state needed to continue. The KV for the sampled token appears when it is subsequently fed through the model. The first output may reach the client before or after the transfer, depending on how the proxy streams.

  4. Move and validate

    A connector can push bytes into reserved decode slots or let decode pull from a producer that keeps the source blocks pinned. A single logical handoff may involve many per-rank, layer, or block transfers, sometimes pipelined with computation. Decode waits for the required blocks, metadata and completion events before it reads them.

  5. Continue or recover

    Decode runs the ordinary token loop. A receiver timeout, cancellation or incompatible layout must leave no partially installed prefix visible to a new request. Lifetimes include in-flight device copies: release or reuse a source or destination block only once the transfer is finished or safely abandoned. Depending on connector and policy, fail the request or reconstruct the lost prefix by recomputing it. A retry after partial streaming must account for tokens already delivered.

Read the two queues separately

If a long prompt gets its first token quickly but token two arrives late, time the wait for decode slots, KV transfer and first decode iteration separately. A fast RDMA link cannot admit a request into a full decode cache. If prefill retains pinned cache pages while decode waits, the backlog can spread to both pools. Attention–FFN disaggregation · AFD

Send a token out, bring its result back

A feed-forward network (FFN) transforms each token after attention mixes information across the sequence. In an MoE block a gate chooses a small number of routed FFN experts. With AFD, attention workers hold the request and KV history while a separate FFN group executes remote layer work. Each split layer introduces a dependency before the hidden state can advance to the next layer.

Permutation groups the assigned rows so each expert receives a batch. Dispatch carries the activation rows and enough routing or ordering metadata to return each result. Combine reverses the mapping and applies the gate weights exactly once. In models with a shared expert or another scaling factor, the model wrapper must add that contribution and preserve residual order. A synchronization barrier or completion event prevents the next layer from consuming unfinished output.

Where the gate runs changes what crosses the link

In a staged example, attention sends a batch of hidden states to an FFN service. That service gates and dispatches internally to expert owners, combines and sends one result per input row back. A direct example gates on attention and sends each expert's rows to its owning FFN rank. The return path combines the contributions. If two experts share a destination, a backend may deduplicate payloads or aggregate their outputs there. Why share an FFN pool?

Two attention replicas may each have only a few tokens for expert 7. Pooling compatible tokens can make its matrix multiply larger and keep fewer copies of its weights. A hot expert, an underfilled return queue or incompatible layer numbers can still stall a microbatch. Group work by model, layer, dtype and execution shape. Reserve receive and permutation buffers at the peak number of assignments, including imbalance and graph padding.

What can overlap?

While FFN computes microbatch A, attention may process an independent microbatch B. Each microbatch needs separate routing maps and live buffers. The next layer for A still waits for its own returned results. On a lightly loaded decode server there may be too little independent work to hide many small messages. Record the unhidden wait at each layer and compare with colocated EP.

Which group owns failures and state?

The attention side owns the request and its KV. An FFN response belongs to a particular forward step, layer, microbatch and row ordering. An extra or stale reply cannot be applied twice. A serving design needs to coordinate aborts and drain outstanding transfers across the participating ranks. Rebuilding a failed expert service requires compatible weights and a healthy group before replay. Actual restart and replay guarantees depend on the runtime.

Compose the cuts

One possible deployment prefills on a full-model pool, transfers its KV once, then decodes using an attention group and a remote expert group. In that case the PD handoff ends at the decode-side cache owner. The AFD exchanges repeat for each split decode layer and each forward iteration. Ordinary EP can route expert tokens within a colocated worker fleet even when there is no separate FFN service. SGLang's proposed composition and boundaries

Read the arithmetic and its limits

PD payload = transferred positions × full-model KV bytes per position
AFD payload = 2 × split layers × rows per layer × width × bytes per element

In the direct toy model, 32 tokens each visit two experts. That sends 64 × 4,096 × 2 bytes, or 512 KiB outward per layer, and the same amount back. Across 32 layers that is 32 MiB. The staged case sends 32 rows per direction for 16 MiB per step. It excludes internal FFN dispatch traffic. Both counts exclude headers, indices, scale tensors, padding, retries and copies through staging buffers.

The time estimate serializes payloads on a single link at your effective rate. Startup cost for many small messages, network topology, computation, overlap, multi-rail placement and full duplex affect real elapsed time. Throughput across both directions is the sum of sent and returned bytes. For the direct example at 50 steps/s, a symmetric link carries about 0.78125 GiB/s in each direction. This is an aggregate group budget. A hot expert's NIC can saturate before the fleet average. Measure per-rank link utilization and message latency.

Can attention and experts use different hardware?

Memory-rich devices may suit long-context attention while another pool offers high expert-matrix throughput. To test a pairing, identify its supported accelerator runtime and collective transport first. CUDA/NCCL and Ascend connectors have distinct backends. Evidence for each ecosystem individually does not establish a direct CUDA-to-Ascend data path.

For PD, match checkpoint revision, tokenizer and template, adapter, position scheme, KV element and scale formats, attention backend, block layout and connector protocol. For AFD also check hidden width, routing weights and normalization, expert ownership and weight packing, supported activation wire dtype, residual semantics, graph capacities and compatible kernel builds on each side. Quantized expert weights and the activation wire format are separate choices. Exercise the exact model, runtime, topology and connector against a known-good colocated result. Deployment exercise

Choose the boundary from a trace

You have two nodes, fast links within each, and a shared network between them. Requests mix long input documents with short chat turns. A weekly traffic spike raises both the first-token tail and the interval between streamed tokens.

  1. Establish a baseline. Use a colocated model and the smallest TP or PP layout that fits the measured peak. Capture offered load, queue time, active KV blocks, expert load, prompt lengths and output lengths. Compare the same data, cold and warm, across trials.
  2. Try PD if the phases interfere. Profile a colocated chunked-prefill alternative. Place the PD boundary where the measured effective link rate can support new prompt KV per second. Check decode destination wait, registration time, transfer p99 and the first-to-second token gap. Include capacity reserved by each pool.
  3. Try AFD when expert batching or duplication is costly. Compare colocated EP first. For the chosen connector, measure per-layer dispatch, FFN queue, expert execution, combine, and time exposed on the decode critical path. Count bubbles and skew when changing the number of A and F ranks. Move the frequently crossed boundary onto the faster fabric when measurements justify it.
  4. Stress the actual deployment. Warm workers and verify comparable outputs before collecting timings. Vary arrival rate, prefix reuse, context length and expert skew. Cancel an in-flight request and check memory recovery. For a worker loss, record failed requests and restart behavior alongside successful goodput and cost per qualifying request.

Dense decoder

Follow one position

Give a decoder the prompt “Tea is”. For this example assume two token IDs. Prefill computes both positions in each layer under a causal mask. The final position’s logits give a distribution over the vocabulary. Suppose the sampler chooses “hot”. On the next step the decoder receives that token and consults the history built for “Tea is”. Actual token boundaries depend on the checkpoint’s tokenizer.

  1. Embed the ID

    A learned table maps each ID to a row with d numbers. For the Llama-8B distill, one row contains 4,096 values. A batch of one two-token prompt starts with a hidden tensor of shape [1, 2, 4,096].

  2. Read earlier positions

    Within each layer, normalization and learned projections produce queries, keys and values. RoPE rotates query and key coordinates to represent position. Attention weights mix values from the permitted positions. A residual connection adds the result back to the input.

  3. Transform each position

    A dense feed-forward network applies the same learned matrices independently at every position. Gated networks combine two intermediate projections before mapping back to d. A second residual addition carries the updated vector onward.

  4. Predict again

    After the last layer, final normalization and a vocabulary projection turn the last hidden vector into logits. The sampler chooses an ID. That new ID gains cache entries when it is fed back through the model.

Count query heads and KV heads separately

At one Llama-8B distill layer and one decode position, the query has shape [1, 1, 32, 128]. New keys and values each have shape [1, 1, 8, 128]. Four query heads share each KV head. This grouped-query attention (GQA) design preserves 32 distinct queries while reducing persistent KV storage.

Assumptions and units

All sequences have the same number of resident positions, with no shared prefix or sliding-window eviction. All backbone layers use their published dimensions. MLA uses the absorbed, compressed cache in the DeepSeek reference implementation. Count the tensors once across the logical model. Device-specific copies, weights, MTP modules, allocator rounding, metadata, temporary buffers and transfer staging have separate budgets. A KiB is 1,024 bytes and a MiB is 1,048,576 bytes. Engine cache formats and placement can change the actual allocation.

Sparse feed-forward layers

Route the token through a subset of weights

In a mixture of experts (MoE), the feed-forward layer contains multiple networks called experts. A learned gate scores them for each hidden vector. Mixtral-8x7B selects two of eight experts per token per layer. Attention still reads grouped KV heads. Mixtral and the Llama-8B distill consequently have the same logical BF16 cache shape in the explorer, even though their weight budgets differ.

Work a four-expert example

Suppose a gate gives E0, E1, E2 and E3 probabilities [0.60, 0.10, 0.25, 0.05]. Top-2 selects E0 and E2. Renormalize their weights to 0.60/0.85 and 0.25/0.85. If one coordinate of their outputs is 2 and 8, the corresponding mixture coordinate is (0.60 × 2 + 0.25 × 8)/0.85 ≈ 3.76. Different tokens can choose overlapping experts, so one worker may receive a disproportionate share of a batch.

Mixtral’s paper reports about 47B total and 13B active parameters per token. The active count describes a compute path. Serving all routes still needs access to the other weights. Expert parallelism distributes those weights and introduces dispatch traffic. Routing also varies by layer and token.

Multi-head latent attention

Read the cache that DeepSeek actually stores

The original DeepSeek-V3 backbone has a width of 7,168 and 61 layers with 128 attention heads. Its first three feed-forward layers are dense. Each of the remaining 58 uses one shared expert plus eight selected from 256 routed experts. The attention mechanism in all 61 layers is MLA.

Conventional attention can cache a key and a value for every KV head. MLA learns a common compressed representation. Matrix absorption moves the content-key up-projection into the query computation, and lets the value up-projection act after the weighted sum. A separate rotated key carries position information. The reference implementation offers both expanded and absorbed execution paths.

Check the unit at every step

One layer retains (512 + 64) × 2 = 1,152 bytes per position in BF16. Across 61 layers that is 70,272 bytes, or 68.625 KiB per position. At 4,096 positions a single sequence needs 274.5 MiB of logical attention state. The 1,536-dimensional query latent serves the current computation and is excluded from this persistent cache.

Inside V3’s group-limited expert choice

The 256 routed experts are organized into eight groups of 32. In the released reference gate, an expert bias adjusts the scores used to select routes. Each group is scored by its two strongest adjusted scores. Four groups remain eligible, then eight experts are selected. Combination weights come from the selected experts’ original affinities, followed by normalization and a scale. The shared expert contributes separately. These choices manage traffic and encourage balance. Actual worker loads still depend on the inputs and expert placement.

Why the V3 release also lists 685B parameters

The published bundle includes roughly 14B parameters for a multi-token prediction (MTP) module alongside the 671B backbone. MTP supplies an additional training signal and can propose future tokens for speculative decoding in a supporting runtime. Verification determines which proposals are accepted. When planning capacity, check which modules the engine loads and how it stores their state. DeepSeek-V3 release notes · Speculative decoding walkthrough

Checkpoint identity

Read the full R1 name before sizing a server

The original full DeepSeek-R1 was developed from DeepSeek-V3-Base. It keeps the 671B-total, 37B-active backbone, including MLA and routed experts. Distillation used examples generated by the teacher to train smaller students. Each student executes its own base architecture when serving a prompt.

Separate checkpoint weights from KV storage

If you represented the 671 billion backbone parameters in BF16, the weight payload alone would be about 1.34 TB in decimal units (671 billion × 2 bytes). Only a subset participates in one token’s computation. A quantized deployment has a different payload and may add scales, padding and other state. The cache explorer above accounts for a different allocation that grows with the workload.

Long reasoning completions add decode steps and retained positions on either architecture. Ask for expected prompt length, output length and concurrency when comparing a small student with its teacher. Guided companion

Inspect DeepSeek-V3 in 2D and 3D

Shiva Nampalli’s DeepSeek Visualizer follows a scripted “The capital of France is” example through 17 steps. The tensor cells, expert scores and next-token probability are deterministic teaching values. Use the reported dimensions to check the cache calculation above.

  1. Open the 2D architecture

    Step through the embedding and MLA stages. Compare one of the first three layers with a later MoE layer in the layer explorer. Locate the shared expert and the routed branch.

  2. Switch to the 3D tensor view

    Select a tensor or matrix cell and inspect its shape. Find the KV latent and rotary key, then identify the activation that exists only for the current query.

  3. Open the MACs report

    One multiply-accumulate is counted as two floating-point operations. A compute estimate helps identify expensive matrix products. To predict latency, also measure memory bandwidth, batch shape and cross-device traffic.

Other sequence models

Check what a new architecture carries forward

Sliding-window and global attention · Gemma 2

Gemma 2 alternates local and global attention layers. If the runtime evicts stale entries in the local layers, each of those layers can retain only its window. Global layers still grow with the full sequence. Sum each layer’s retained positions separately before applying a byte-per-position estimate. Gemma 2 report

Recurrent state-space layers · Mamba

A selective state-space layer updates a per-sequence recurrent state and convolution history. At decode time its state shape is fixed for a given layer, even as more tokens arrive. A hybrid model with attention layers still needs those layers’ KV histories. Track state with the formula for each layer type. Mamba paper

Encoder–decoder models · T5

The encoder processes the whole source sequence once. Decoder self-attention reads previously generated positions, while cross-attention reads representations from the source. There are two length variables: the source length fixes the cross-attention memory and the generated length grows the decoder history. T5 paper

Runtime connection

Translate shapes into serving decisions

  • Weights exceed one device. Separate total checkpoint bytes from active arithmetic. Tensor sharding, pipeline stages and expert placement put different kinds of traffic on the fabric. Explore GPU layouts.
  • Short chats fit, long chats fail. Calculate attention-state bytes for the actual architecture and count resident positions across concurrent requests. Compare that payload with physical cache blocks, metadata and free capacity. Follow the engine memory lifecycle.
  • Theoretical savings miss the latency target. Inspect prefill and decode separately, then measure attention kernels, weight reads, dispatch and queueing at representative load. Build a serving measurement.
  • You want to trace the arithmetic locally. Inspect this repository’s small grouped-query attention implementation, then step through a real toy-model request.
